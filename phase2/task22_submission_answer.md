For Task 22, I stood up a governed A/B experimentation framework that connects experiment design, stable assignment, outcome measurement, data-subject rights and resilience controls. The framework defines a complete lifecycle from experiment draft and approval through assignment, exposure, analysis, decision and archival. The primary metric, denominator, analysis window, guardrails and decision rules are specified before an experiment is considered ready to run.

The implementation uses a synthetic dry-run experiment so the mechanics can be demonstrated without presenting fabricated PlaceMux production performance. The example experiment uses a deterministic 50/50 subject-level assignment and a 7-day application-submission metric. The framework records eligible subjects, assignment, confirmed exposure, application progression, interviews and offers, while keeping the experiment population and variant logic explicit and reproducible.

Data-subject rights are enforced before experimentation exposure and analysis. Subjects without required consent, with a deletion request, or with experiment withdrawal are excluded from the governed population. Consent version and purpose metadata are retained with the experiment state, and the tracking plan includes explicit `consent_withdrawn` and `deletion_requested` events. The model also uses opaque subject identifiers and defines least-privilege access and controlled retention/deletion of derived experiment data.

Resilience is built into the framework through stable deterministic assignment, immutable first assignment, exposure-versus-assignment separation, variant consistency checks, duplicate detection, allocation-balance tolerance, lifecycle ordering rules and machine-readable validation. The dry run passed all defined integrity and rights checks. The resulting dashboard shows experiment design, primary results, guardrails, data-subject controls and resilience status in one place.

The repository deliverables are `phase2/ab_experiment_metrics.md`, `phase2/ab_experiment_tracking_plan.md`, `phase2/ab_experiment_model.md`, `phase2/ab_experiment_demo.py`, `phase2/ab_experiment_events_demo.csv`, `phase2/ab_experiment_results.csv`, `phase2/ab_experiment_validation.json`, and `phase2/ab_experiment_dashboard.html`. Together these provide the metric contract, event taxonomy, logical model, reproducible calculations, validation evidence and demo-ready dashboard required to operationalize the A/B framework.
