For Phase 3 Task 2, I built a single semantic and metric layer designed to ensure that the same business question returns the same number across dashboard, executive reporting and ad-hoc analysis. The framework defines each governed metric with one business definition, formula, source fields, grain, owner, refresh SLA and decision use. The published metric dictionary contains ten core metrics covering transaction volume, trusted purchase population, revenue, customer coverage, repeat activity and data quality.

Because the PlaceMux brief does not provide a production data export, the implementation is demonstrated on the real UCI Online Retail dataset already used in the project as an explicit external-data proxy. The source is read directly from `data/online_retail/Online Retail.xlsx`, and the semantic layer applies deterministic transaction-state and numeric-quality rules before calculating downstream metrics. This is a real-data implementation of the metric framework, not a claim about PlaceMux production telemetry.

The data-quality layer checks freshness metadata, source volume, required-field nulls, uniqueness and semantic validity. CustomerID null rate, cancellation rate, invalid quantity rate and invalid price rate are surfaced explicitly because they change the trustworthiness of customer and commercial metrics. Alert states are standardized as PASS, WATCH and BLOCKED so that quality failures can stop publication rather than silently propagating.

I also implemented metric-parity validation across three consumer surfaces: dashboard, executive view and ad-hoc query. All three read the same semantic values, and a deliberate downstream tampering test is included to prove that a mismatch is detected rather than accepted. This gives the framework a visible failure path and supports the task requirement to demonstrate resilience rather than only happy-path output.

The completed deliverables are `metric_semantic_layer.py`, `metric_dictionary.md`, `task2_tracking_plan.md`, `data_quality_and_alerting.md`, the generated metric dictionary and validation outputs, and `task2_dashboard.html`. Together they provide a reproducible semantic layer, published metric contract, quality-alerting model and demo surface. Production adoption would require mapping the same contracts to PlaceMux event tables and production ingestion timestamps when those sources are available.
